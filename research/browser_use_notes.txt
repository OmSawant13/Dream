# BROWSER-USE: MODULAR AGENTIC ARCHITECTURE
(Deep Research Notes)

## 1. THE OBSERVATION LOOP (The 'Double-Check')
- **Logic:** Observation = AXTree Snapshot + Current Screenshot.
- **Self-Correction Algorithm:** After an action, it compares the 'New Screenshot' to the 'Old Screenshot'. 
- **The "Stale Selector" Fix:** If the visual state hasn't changed but the LLM thinks it clicked, it triggers a 'Deep Refresh' and re-indexes the page elements.

## 2. MODULAR ACTION WRAPPERS
- **Design Pattern:** It doesn't give the LLM raw Playwright access. It exposes a 'Toolbox' of simplified actions:
  - `click_element(index)`
  - `input_text(index, text)`
  - `scroll_to_view(index)`
- **Safety:** Every tool call is validated against the current `element_map` before being converted to Playwright commands.

## 3. MULTI-FRAME COORDINATION
- **Architecture:** `browser-use` is exceptional at handling Iframes. It recursively traverses every frame on the page and flattens them into a single, unified 'Semantic View' for the LLM. 
- **Insight:** This allows Papper to click things inside complex third-party embeds (like chat widgets or payment forms) seamlessly.

## 4. MEMORY MANAGEMENT
- **Approach:** It maintains a 'Last N Actions' history window. This prevents the agent from getting stuck in an 'Infinite Click' loop on the same button.
