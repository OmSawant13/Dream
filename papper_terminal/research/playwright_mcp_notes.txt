# PLAYWRIGHT-MCP: THE OFFICIAL BRIDGE
(Deep Research Notes from Microsoft)

## 1. THE PROTOCOL: MCP (Model Context Protocol)
- **Concept:** Instead of a custom 'Agent,' this is a 'Server' that gives the LLM direct access to browser capabilities.
- **Tooling Schema:** Uses **Zod** to strictly define the parameters for every tool (`navigate`, `click`, `fill`, etc.). This eliminates 'Schema Mismatch' errors.

## 2. THE PERCEPTION STANDARD: AXTree
- **Insight:** Microsoft engineers chose the **Accessibility Tree** as the primary sensory input. 
- **Algorithm:** It uses `page.accessibility.snapshot()` to create a structured JSON tree. 
- **LEVERAGE:** This is the most efficient way to communicate with LLMs. It contains 'Role', 'Name', and 'Value'—the three pieces of data an AI needs to make a decision.

## 3. GRANULAR VERIFICATION (`browser_verify`)
- **Tool:** A dedicated 'Verification' tool.
- **Logic:** Instead of just clicking and assuming success, the LLM is encouraged to call `verify` to check for specific text, elements, or URL changes. 
- **LEVERAGE:** We should incorporate a `verify_state` action in Papper to make her 'Self-Aware'.

## 4. CONSOLE & NETWORK TELEMETRY
- **Feature:** It pipes browser console logs and network errors directly into the LLM's context.
- **Why:** If a button click fails because of a '403 Forbidden' or a JS error, the LLM sees the error and can 'Diagnose' the issue like a real developer.
