# BROWSER-AGENT: GRAPH-BASED REASONING
(Deep Research Notes on rkvalandas/browser_agent)

## 1. THE ARCHITECTURE: REASONING GRAPH
- **Logic:** It doesn't use a simple 'Next Step' loop. It uses a 'Graph' of possible states. 
- **Algorithm:** The agent maintains a 'Mental Map' of where it is in the task. Each node in the graph is a 'State' (e.g., 'On Search Results Page').
- **Decision:** The LLM decides the 'Edge' to take (e.g., 'Click first result' or 'Scroll down').

## 2. DYNAMIC SELECTOR GENERATION
- **Secret:** It doesn't rely on pre-defined IDs. If a click fails, the agent uses a tool to 'Inspect Element' and generates a fresh, robust CSS/XPath selector on the fly.
- **Resilience:** This allows the agent to survive UI changes or A/B tests that would break traditional scripts.

## 3. EVIDENCE-BASED AUTONOMY
- **Pattern:** `Analyze -> Execute -> Verify -> Adapt`.
- **Logic:** Before taking an action, it must find 'Evidence' that the action is correct (e.g., 'I see a shopping cart icon, so I should click here to checkout').

## 4. OVERLAY & MODAL DETECTION
- **Logic:** It has a dedicated 'Perception Phase' for blocking elements. It specifically looks for `z-index` and `opacity` to find hidden modals or 'Cookie Consent' banners that might be blocking the target.
